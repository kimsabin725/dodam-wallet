# 도담월렛 (Dodam Wallet)

> **아이 앞으로 있는 돈은 많은데, 아이 손에 쥐여줄 방법이 없다.**
>
> 아이 앞 자산(세뱃돈·용돈·증여 예금)의 **원본은 지키면서**, 부모가 말로 설계한 조건 —
> *"분식·문구·서점에서만, 월 5만원, 우리 동네 지정 가게"* — 대로 용돈만 흘려보낸다.
> 조건 밖 결제는 **실행 자체가 되지 않고**, 모든 지출은 고칠 수 없는 기록으로 남아
> **"자녀가 실제로 사용했다"는 증여 세무 증빙**이 된다.

npm run build:single   # ★ dist-single/dodam-wallet.html — 파일 하나, 더블클릭으로 실행

### 심사용: 설치 없이 여는 법

```bash
npm run build:single
open dist-single/dodam-wallet.html      # Windows: 더블클릭
```

**HTML 파일 하나(174KB)에 전부 들어 있다.** 서버도, `npm`도, 인터넷도 필요 없다.
브라우저로 열면 그대로 돈다 — 심사장에서 코드를 돌리지 않아도 시연이 가능하다.
빌드 스크립트가 외부 참조가 하나라도 남으면 실패하므로, 산출물은 항상 자족적이다.

**요구사항은 Node.js 하나뿐이다** (18·20·22 이상 — Vite 요구사항. LTS 권장). 백엔드도, 데이터베이스도, API 키도 필요 없다.
**인터넷 연결 없이 전 기능이 동작한다** — 심사장 네트워크가 죽어도 데모는 그대로 돌아간다.

## 3분 시연 대본

> 화면 상단의 `① 조건 설정 → ② 결제 → ③ 리포트` 순으로 따라가면 된다.

### ① 조건 설정 — 30초
입력창에 이미 예시 문장이 들어 있다.

```
분식이랑 문구점, 서점까지. 한 달에 5만원. 한 번에 만원까지.
게임은 안 돼. 우리 동네 지정한 가게에서만.
```

**[AI로 조건 변환]** → 조건 카드가 뜬다. 카드는 **그 자리에서 고칠 수 있다**
(업종 켜고 끄기, 지정 가맹 스위치, 한도 숫자). 잘못된 조건이면 발행 버튼이 잠긴다.

**[조건 심어서 발행하기]** → 아이 폰으로 넘어간다.

### ② 결제 — 90초
왼쪽이 아이 폰, 오른쪽이 부모 폰이다. **가맹점 타일을 위에서부터 차례로** 누른다.
탭하면 결제 시트가 올라오고, 금액을 바꿔서 결제해 볼 수도 있다.

| 순서 | 가맹점 | 금액 | 결과 |
|---|---|---|---|
| 1 | 🍢 학교앞분식 *(분식·지정)* | 3,500 | ✅ 승인 |
| 2 | 🎮 게임아이템샵 | 9,900 | ❌ 차단된 사용처예요 |
| 3 | ✏️ 우리문구 *(문구·지정)* | 2,500 | ✅ 승인 |
| 4 | 🧁 달콤분식 *(분식·**미지정**)* | 4,000 | ❌ 지정 가맹점이 아니에요 |
| 5 | 📚 푸른동네서점 | 9,800 | ✅ 승인 |
| 6 | 🧺 다이소 *(**미지정 대형매장**)* | 5,000 | ❌ 지정 가맹점이 아니에요 |
| 7 | 🍙 신천김밥 | 7,000 | ✅ 승인 |
| 8 | 🎤 코인노래방 *(오락)* | 4,000 | ❌ 조건에 없는 업종이에요 |
| 9 | 🌶️ 반월당떡볶이 | 9,000 | ✅ 승인 |
| 10 | 🔥 떡볶이월드 *(12,000원)* | 12,000 | ❌ 1회 한도(10,000원)를 넘었어요 |
| 11 | ✒️ 칠성문구 | 9,000 | ✅ 승인 |
| 12 | 📖 동성로책방 *(누적 40,800원)* | 9,800 | ❌ **이번 달 한도를 넘었어요** |

> **킬러 컷 ①** — 같은 분식집인데 **학교앞분식은 승인, 달콤분식은 차단**된다.
> "우리 동네 지정한 가게"라는 부모의 한마디가 그대로 실행되는 장면이다.
>
> **킬러 컷 ②** — **다이소는 막히고 골목은 열린다.** 용돈이 대형매장이 아니라
> 동네 문방구·분식으로 흐른다.

누를 때마다 **부모 폰에 실시간 알림**이 뜬다. 승인 건에는 "수수료 0 정산" 배지가,
차단 건에는 사유가 그대로 붙는다. 위 12칸을 다 누르면 **판정 6종이 전부** 나온다
(『지정 가맹점이 아니에요』만 두 번 — 달콤분식과 다이소는 **서로 다른 이야기**를 하기 때문이다.
하나는 *같은 업종인데 지정 안 된 골목 가게*, 하나는 *지정 안 된 대형매장*).

부모 폰 상단 자산 카드의 **이자는 초 단위로 올라간다** — *"결제를 기다리는 돈도 하루도 쉬지 않는다."*

### ③ 리포트 — 60초
- **[체인 검증]** → 초록. 모든 블록이 이전 블록 해시로 연결돼 있음을 재계산으로 확인
- **[변조 시연]** → 1번 블록 금액을 몰래 +10,000원 고친다 → 다시 **[체인 검증]** →
  **빨강, 검증 실패.** "고칠 수 없다"를 말이 아니라 **실패로** 보여준다
- **[증빙 리포트 열기]** → 증여 실질 입증 리포트. 기간·조건·지출 합계·**차단 건수**·
  업종별 분포·체인 서명. **인쇄/PDF 저장**까지 된다
- **[씨앗적금으로 이동]** → 미사용 9,200원이 적금으로. *낙전 대신 저축이 기본값*
- **[제안 수락]** → "중학교 진학 — 카테고리 방식으로 전환할까요?" *아이가 크면 조건도 자란다*

> 상단 **[리셋]**으로 언제든 처음부터 다시 시연할 수 있다.

│    ledger.js    SHA-256 해시 체인 (append / verify / tamper) │

│    condition.js 스키마 · 정규화 · 검증                        │

| 결정 | 내용 | 이유 |
|---|---|---|
| 백엔드 없음 | Vite + React SPA, 정적 빌드 | 서버 = 시연 리스크. 오프라인 동작 |
| 판정은 순수 함수 | `judge(merchant, amount, cond, ledger)` | 테스트 비용이 낮고 신뢰 이득이 큼 |
| 원장은 클라이언트 해시 체인 | Web Crypto SHA-256 | 변조 시연까지 브라우저에서 가능 |
| AI는 룰 파서가 기본 | Claude는 선택 모드 | 네트워크 없이도 전 기능 동작 |
| 스타일은 플레인 CSS | Tailwind 미사용 | 빌드 설정 리스크 제거 |

### 판정 엔진 — 사유 문자열이 그대로 알림 문구다

`src/core/judge.js`. 다음 순서로 검사하고, 먼저 걸리는 것이 사유가 된다.

| # | 검사 | 사유 문구 |
|---|---|---|
| 1 | 차단 업종인가 | `차단된 사용처예요` |
| 2 | 허용 업종 밖인가 | `조건에 없는 업종이에요` |
| 3 | 지정 가맹 모드인데 미지정인가 | `지정 가맹점이 아니에요` |
| 4 | 회당 한도 초과인가 | `1회 한도(10,000원)를 넘었어요` |
| 5 | 월 누적 + 이번 결제 > 월 한도인가 | `이번 달 한도를 넘었어요` |
| 6 | 전부 통과 | **승인** |

> 순서가 중요하다. 업종을 지정 여부보다 **먼저** 봐야 "같은 분식집인데 지정 안 된 곳"이
> `지정 가맹점이 아니에요`라는 정확한 사유를 낸다.

### 해시 체인 원장

`src/core/ledger.js`. 블록 하나는 이렇게 생겼다.

```js
{ seq, ts, merchant, amount, result, reason, prevHash, hash }
//                                            ▲        ▲
//                        이전 블록의 hash ────┘        └── SHA256(위 전체를 직렬화)
```

해시는 Web Crypto(`crypto.subtle`)로 계산하고, 그것이 없는 환경에서는 순수 구현
(`core/sha256.js`)으로 넘어간다. **파일을 더블클릭해 여는 배포본에서도 원장이 동작해야** 하기
때문이다. 두 경로가 같은 값을 낸다는 것은 `tests/sha256.test.js`가 블록 경계까지 검증한다.

- `append()` — 이전 해시를 물려 새 블록을 잇는다 (append-only)
- `verify()` — 전체를 재계산해 `prevHash` 연결과 각 `hash`를 검증
- `tamper(i)` — **시연용**. i번 블록 금액만 고친 사본을 반환 → `verify()`가 실패한다

승인뿐 아니라 **차단도 블록으로 남는다.** 증빙 리포트에서 이게 핵심이다 —
*조건 밖 시도가 실행되지 않았다는 증거*가 되기 때문이다.

### AI — 두 경로, 어느 쪽이 죽어도 데모는 산다

```
부모의 문장
    │
    ├─ API 키 없음 ──────────────► core/parser.js (룰 파서)   [AI 오프라인 모드]
    │
    └─ API 키 있음 ─► Claude API ─┬─ 성공 + 검증 통과 ──────► 조건    [Claude 온라인]
                                  └─ 실패·거절·검증 실패 ──► 룰 파서  [폴백]
```

- **키는 `localStorage`에만 있다.** 저장소·코드·빌드 산출물 어디에도 시크릿이 없다
- 어느 단계에서 실패하든(네트워크, JSON 파싱, 안전 거절, 스키마 위반) **조용히 룰 파서로 되돌아간다**
- **AI가 준 조건도 검증을 통과해야 쓴다** (`condition.js`의 `validate()`).
  목록 밖 업종이 섞이면 그 조건은 영원히 매칭되지 않아 **판정이 조용히 틀리기** 때문이다

키를 넣으려면 상단 **⚙** 버튼. 넣지 않아도 데모의 모든 기능이 동작한다.

## 프로젝트 한강 2단계 접속 설계

iM뱅크는 한국은행 **프로젝트 한강 2단계**(예금토큰) 실증 참여 은행이다(2026-07-15 혁신금융서비스 신규 지정, [아시아경제](https://view.asiae.co.kr/article/2026071517484622411)).
이 프로토타입의 판정·원장 층은 그 레일에 **그대로 얹히도록** 설계했다.

```
        [ 지금 — 이 프로토타입이 시연하는 것 ]
   부모 조건 ──► 판정 엔진 ──► 체크카드 레일 (만 7세+, 시행 중)
                    │              수수료 0 직불 / 정산 D+1~2
                    └──► 해시 체인 원장 ──► 증여 실질 입증 리포트

                              ⇩  같은 조건, 같은 원장, 레일만 교체

        [ 접속 후 — 예금토큰 단계 ]
   부모 조건 ──► 판정 엔진 ──► 예금토큰 조건부 지급 (프로젝트 한강 2단계)
                    │              원본 예금 유지 · 즉시 정산
                    └──► 원장이 곧 제도권 거래 기록
```

**바뀌는 것은 지급 레일 하나뿐이다.** 조건 스키마, 판정 순서, 원장 구조는 그대로다.
정부가 바우처·보조금으로 검증 중인 프로그래머블 머니를 **민간(가족 자산)으로 확장**하는 경로다.

> ⚠️ 한강 실증의 이용자 요건상 **미성년 지갑 적용은 아직 미확정**이다.
> 그래서 1단계는 이미 시행 중인 체크카드 레일로 구현하고, 예금토큰은 **접속 가능 설계**로 둔다.

**`demo.test.js`가 특별하다.** 위 3분 대본의 12칸 판정 결과가 전부 여기 고정되어 있다.
가맹점 데이터나 판정 순서가 바뀌어 시연이 어긋나면 **테스트가 먼저 깨진다.**
대본이 문서가 아니라 실행 가능한 명세다.

## 범위 — 만들지 않은 것

이건 **시나리오 시연용 프로토타입**이다. 다음은 의도적으로 만들지 않았다.

- 회원가입·로그인·본인인증
- 실제 결제 처리 및 카드사 연동
- 백엔드 서버·데이터베이스
- 예금토큰 실연동 (위 접속 다이어그램으로 설계만 제시)

**한계**
- 가맹점 12곳과 자산 수치는 시연용 고정 데이터다 (대구 학교앞 상권 톤)
- 해시 체인은 브라우저 안의 단일 클라이언트 체인이다. 분산 합의는 범위 밖이며,
  이 단계에서 증명하려는 것은 **불변성과 검증 가능성**이다
- **즉시 정산은 예금토큰 단계에서만 성립한다.** 지금 주장하는 것은 *수수료 0*이다
  (제로페이 레일도 정산은 D+1~2)
- 이자 시연은 **증여 원본 카드에서만** 한다. 용돈 잔액(수만원 × 요구불 금리)에서는
  수치가 성립하지 않는다

## 파일 지도

```
src/
├── App.jsx                 상단 레일(단계·설정·리셋) + 화면 전환
├── store.js                useReducer 스토어 + localStorage 저장/복원
├── ai.js                   자연어→조건 (룰 파서 기본 · Claude 선택)
├── core/                   ★ 순수 함수 층 — 전부 테스트 대상
│   ├── judge.js            판정 엔진
│   ├── ledger.js           SHA-256 해시 체인
│   ├── parser.js           룰 기반 자연어 파서
│   └── condition.js        스키마 · 정규화 · 검증
├── data/
│   ├── merchants.js        가맹점 12곳 (시연 대본과 1:1)
│   └── templates.js        연령별 조건 기본값 4종
├── screens/
│   ├── Setup.jsx           ① 조건 설정 (편집 가능한 조건 카드)
│   ├── PayDemo.jsx         ② 결제 (아이 폰 ↔ 부모 폰 스플릿뷰)
│   └── Report.jsx          ③ 리포트 (체인 · 증빙 · 스윕 · 이양)
└── components/
    ├── Modal.jsx           공용 모달 (ESC · 배경 클릭)
    ├── PaySheet.jsx        결제 시트 (금액 수정 가능)
    ├── Gauge.jsx           월 한도 게이지 (소진 시 색 전환)
    ├── InterestCounter.jsx 원본 이자 실시간 카운터
    ├── ProofReport.jsx     증여 실질 입증 리포트 (인쇄 지원)
    └── SettingsModal.jsx   Claude API 키 입력
```
